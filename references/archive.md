## 1. 为什么需要错题档案

一张卷子的分析，老师讲评已经覆盖了不少。可如果连续几次考试都在同一个知识点丢分，只有把记录串起来才看得出来。错题档案就是这条记录：每道错题都挂着一个稳定的知识点 ID，跨考试统计按 ID 匹配，不会因为这次写"含参单调性"、下次写"含参函数单调性"就对不上。

## 2. 保存在哪里

对话之间默认不会互相记得，所以档案必须存成文件，并且每次都能找到：

| 环境 | 做法 |
|---|---|
| 能长期保存文件的环境（Claude Code、绑定了本地文件夹的桌面版） | 固定放在 `~/错题档案/错题档案.json`。每次开始时先找这个文件，结束时写回去，并告诉学生路径。 |
| 网页版、App 等每次对话都是新环境的 | 每次结束时把更新后的档案文件交给学生。建议学生建一个 Claude 项目（例如"错题复盘"），把档案放进项目文件里，每次在这个项目里开新对话；每次用新档案替换旧的。也可以下次和新试卷一起上传。 |

不要把档案只放在跨对话记忆里。记忆里可以有一句摘要（年级、教材版本、档案在哪、反复出错的知识点），但档案文件才是依据。

找不到档案时，先问一句学生以前有没有用过（可以放进确认卡）；确定是第一次，就新建。

## 3. 文件格式

UTF-8 编码的 JSON：

```json
{
 "version": 1,
 "profile": {"stage": "高中", "grade": "高三", "textbooks": {"数学": "人教A版"}, "updated": "2026-11-18"},
 "exams": [
  {"date": "2026-03-05", "name": "高三一模", "subject": "数学", "score": 133, "full": 150,
   "notes": "21:00 开考，22:20 做完第 14 题"}
 ],
 "mistakes": [
  {"id": "2026-03-05-数学-19(3)", "exam_date": "2026-03-05", "exam_name": "高三一模",
   "subject": "数学", "question": "19(3)",
   "kp_id": "GZ-SX-15-03", "kp_name": "导数在研究函数中的应用", "related_kp_ids": ["GZ-SX-04-03"],
   "category": "思路盲区", "detail": "单调性和图象已得出，没想到用特殊点 −π 卡住中间的零点",
   "stuck_point": "比较 xq 与 (xp+xr)/2", "points_lost": "3", "source": "学生",
   "status": "待重做", "correct_count": 0, "last_review": "", "next_review": "2026-11-18"}
 ]
}
```

- `id` 由脚本生成：`考试日期-科目-题号`。
- `category` 只能是：基础漏洞、思路盲区、习惯失误、时间与策略。
- `source`：学生说的填"学生"，你推测的填"推测"。
- 科目写"数学、物理、化学、生物、语文、英语、政治、历史、地理"之一；"道德与法治""思想政治"统一记为"政治"。
- 不写学生姓名、学校等身份信息。

## 4. 给错题挂知识点

- 每道错题 1 个主知识点（`kp_id`），必要时最多 2 个相关知识点（`related_kp_ids`）。相关知识点是"这道题没做出来，也和它有关"的前置知识，例如导数压轴题卡在零点估计，相关知识点挂"函数的零点"。
- ID 一律从 `knowledge-map/<科目>.md` 里查（`archive.py kp-search`），不要自己编。`merge` 会拒绝地图里不存在的 ID。
- 档案里已有的知识点，沿用同一个 ID。
- 地图里找不到合适条目时，`kp_id` 留空，只写 `kp_name`。脚本会把它按名称归类，但名称匹配不可靠，报告里要注明"未匹配"。
- 粒度：知识点应该是"可以单独找题来练的一个小点"。地图里的条目已经按这个粒度划分，选最贴近的那一条。

## 5. 状态与复习节奏

| 情况 | 状态 | 下次复习 |
|---|---|---|
| 新入库 | 待重做 | 当天（复盘当天就闭卷重做） |
| 闭卷独立做对第 1 次 | 二刷 | 7 天后 |
| 连续第 2 次闭卷独立做对 | 已掌握 | 30 天后（回看一次） |
| 已掌握后回看仍然做对 | 已掌握 | 无（完成） |
| 任何一次没做对或卡住 | 待重做（连续做对次数清零） | 1 天后 |

另外建议学生在复盘第二天把错题卡快速回看一遍，这一步不需要记录。

## 6. 用 scripts/archive.py 操作

只用 Python 标准库。带日期的命令都可以加 `--today YYYY-MM-DD`，不加就用系统日期。学生上传的档案可能放在只读位置，先复制到可写的输出目录，再对副本操作。

```bash
# 新建档案，或更新学生信息
python scripts/archive.py init --archive 错题档案.json --stage 高中 --grade 高三 --textbook 数学=人教A版

# 查知识点 ID（关键词用教材里的说法；可以给多个，按命中个数排序）
python scripts/archive.py kp-search --subject 数学 --stage 高中 --q 导数 --q 零点

# 写入本次考试和错题。本次.json 的格式：{"exam": {...}, "mistakes": [{...}, ...]}
python scripts/archive.py merge --archive 错题档案.json --new 本次.json

# 记录一次闭卷重做的结果
python scripts/archive.py update --archive 错题档案.json --id 2026-03-05-数学-19(3) --result pass

# 列出今天该复习的题
python scripts/archive.py due --archive 错题档案.json

# 跨考试报告（Markdown）
python scripts/archive.py report --archive 错题档案.json --subject 数学
```

`kp-search` 是按字面匹配的。知识点名称沿用教材的课题或节名，按概念搜不到时（例如高中历史搜"洋务"），换成课题名、单元名再搜，或者用下面的命令列出整张地图，按单元去找：

```bash
python scripts/archive.py kp-search --subject 历史 --stage 高中 --limit 300
```

`merge` 的提示要逐条看：知识点 ID 不在地图里、错因类别写错、丢分不是数字，都会列出来。

## 7. 怎样写"可能没掌握的知识点"和"和以前比"

`report` 输出里有几张表：

- **可能没掌握的知识点**：在 2 次及以上考试中出错（作为主知识点或相关知识点都算）。写进报告的知识点星图，标为反复出错，附证据和"回到教材"的位置。只出现过一次的，不要说"没掌握"。
- **反复出错的单元**：同一单元在 2 次及以上考试中、累计 3 道及以上错题。说明问题可能不只是一个点，而是整个单元。可以在共同病因或下周行动里提。
- **最近一次考试涉及的知识点**：每个知识点以前错过几次。
- **每次考试各类错因丢分**：用来写"和以前比"，例如"习惯失误丢分：15 分 → 11 分"。有进步一定写出来。
- **还没掌握的题**：积压很多时，建议先清掉积压，再处理新错题。
